# Documentation Creation Restrictions

## Prohibited Documentation Creation

**NEVER create, generate, or write any of the following types of documentation files:**

- Summary documents or reports
- Reference documentation or API docs
- User guides, tutorials, or how-to documents
- README files or project documentation
- Architecture documentation or design docs
- Process documentation or workflow guides
- Meeting notes, status reports, or project updates
- Changelog or release notes
- Code documentation beyond inline comments
- Configuration guides or setup instructions

## Allowed Documentation Activities

**ONLY the following documentation activities are permitted:**

- Inline code comments for complex logic
- JSDoc comments for functions and classes
- Brief commit messages
- Error messages and user-facing text
- Configuration file comments
- Type definitions and interfaces

## Implementation Guidelines

- Focus on **code implementation** rather than documentation
- Provide **working solutions** instead of explanatory documents
- Keep responses **action-oriented** and **implementation-focused**

## Response Behavior

When asked to create documentation:
1. Offer to implement the actual functionality instead
2. Focus on solving the underlying problem with code
3. Provide minimal, actionable responses

**Remember:** Code is the primary deliverable, not documentation.
